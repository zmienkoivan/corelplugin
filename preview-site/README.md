# Vanya Preview

## Масштаб превью на рабочем месте

В настройках можно выбрать начальный масштаб 50–100% от изображения, вписанного
в холст. По умолчанию используется 85%. Выбор сохраняется в браузере и применяется
при открытии кадра, полноэкранного просмотра и нажатии «Вписать». Ручное приближение
не сбрасывается при фоновом обновлении списка заказов.

## Фото для клиентской этикетки

При печати клиентской этикетки с сайта используется кадр, открытый в превью в момент
нажатия «Этикетка». Выбор передаётся в браузерную, локальную и общую очередь печати.
Номер фото сохраняется вместе с заданием: повтор запроса проверяет исходное задание
и не заменяет его другим кадром. Для старых локальных модулей сайт использует общую
очередь того же зарегистрированного принтера; обновлённый модуль поддерживает выбор напрямую.

## Фото и комментарии с телефона

Иконка QR справа под карандашом открывает временную ссылку к выбранному заказу.
Ссылка действует 15 минут и позволяет создать одну заметку с комментарием и до 10 фото.
На телефоне доступны камера и выбор нескольких файлов; вход и ключ сервера не нужны.
Снимки сжимаются перед загрузкой, повторная отправка не создаёт дубль заметки.

Сигналы новых карточек и готовности настраиваются отдельно на каждом рабочем месте:
включение звука, громкость, проверка и уведомления браузера.

## Удаление ненужных заказов

Кнопка корзины на сайте требует подтверждения номера заказа и текущей версии
карточки. Заказ убирается из рабочих списков сайта и плагина, его системные сообщения
и фотографии удаляются из Telegram. Текст, фотографии, номер и причина удаления сохраняются
в базе (`deleted_at`, `deletion_reason`), номера повторно не используются.
Bot API не разрешает удаление сообщений старше 48 часов: при отказе `message can't
be deleted` бот заменяет их статус на «🗄️ Архив», убирает кнопки и закрепление.
Очередь `order_telegram_cleanup` сохраняется вместе с архивированием в одной
транзакции. До удаления сообщений все полные фотографии сохраняются в серверном
кэше; при ошибке сохранения удаление Telegram откладывается. Сбой связи повторяется после перезапуска; уже удалённые части альбома
не обрабатываются заново. Обрабатываются только ID сообщений конкретного заказа,
по явно подтверждённой корзине. Ранее архивированные карточки автоматически не удаляются.
При удалении основного системного сообщения непосредственно в Telegram бот
проверяет его существование примерно раз в минуту. Два ответа «message to edit
not found» или «MESSAGE_ID_INVALID» для положительного ID подтверждённой системной публикации
с интервалом не меньше минуты при подтверждённых правах администратора
убирают карточку из рабочих списков. Отдельные фотографии старых альбомов не
определяют удаление всего заказа. Ошибки связи, ограничения Telegram, потеря прав
и сообщения из других каналов не приводят к архивированию.
Изменение текста и фото архивной карточки не возвращает заказ в рабочий список.

## Перенос старых заказов пересылкой Telegram

Для редактирования меняйте текст и фотографии **системной карточки с номером заказа**
в рабочем канале. Сохраняйте имя, источник и технологию; описание и количество
можно исправлять свободно. После сохранения нажмите «🔄 Обновить карточку» под
сообщением: бот прочитает актуальное содержимое из ответа на нажатие, даже если
Telegram не доставил событие редактирования. Номер, срок, готовность и паузы
сохраняются. Другие рабочие кнопки также сначала учитывают правку текста и фото.
Подписка на `edited_channel_post` продолжает обрабатывать доставленные правки автоматически.

При `ORDER_IMPORT_LEGACY=1` можно переслать старую карточку в настроенный канал
или в личные сообщения боту. Личный импорт доступен сотрудникам из
`ORDER_BOT_ALLOWED_USER_IDS`; обычные личные сообщения не создают заказов.
Бот ждёт примерно четыре секунды после последней части фотоальбома, разбирает
имя, источник и технологию, переносит фотографии и произвольные комментарии.
Для каждого заказа пересылайте весь его альбом одним действием. Несколько
разных карточек можно переслать вместе: отдельные сообщения/альбомы разбираются отдельно.
«ПУФ» (также «ПУФФ», PUF и PUFF) распознаётся как отдельный тип нанесения
на основе шелкографии. Написание не зависит от регистра; свободный текст,
включая количества по цветам без единиц измерения, сохраняется без изменений.

Новая системная карточка публикуется в настроенный канал и появляется на сайте
с новым номером. В личке бот отвечает этим номером и ссылкой; пересылка в личке
сохраняется. При пересылке в канал бот удаляет только новую пересланную копию
после подтверждения полной системной карточки. Исходный старый канал не меняется.
Старый системный номер и строка статуса не попадают в новый текст карточки;
распознанные срок и срочность сохраняются. Импортированный заказ начинает работу
с состоянием «В работе».

Пересылка существующей системной карточки создаёт отдельный заказ с новым
номером, теми же фотографиями и текстом; исходный заказ сохраняется. Каждая
новая пересылка такой карточки означает новый дубль. Повторная доставка того же
сообщения или альбома не создаёт лишних копий, в том числе после перезапуска.
Альбом из частей разных системных заказов остаётся для проверки.
Повторная пересылка старого сообщения сотрудника с теми же исходными ID
не создаёт второй заказ. Для пересылок от пользователей без открытых ID
используется сочетание источника, даты, текста и фото. Если часть альбома уже
импортирована или публикация не подтверждена, бот оставляет пересылку для проверки.
Если имя, источник или технология не распознаны, оригиналы сохраняются;
в личке бот сообщает, чего не хватает. Прежняя история канала не сканируется:
обрабатываются только новые поступившие пересылки.

## Состояния производства

У каждой карточки пять действий: **🔥 Готов / 🌲 Вернуть в работу**,
**⏸ Заготовки пауза / ▶ Заготовки продолжить**,
**⏸ Нанесение пауза / ▶ Нанесение продолжить**, **⚡ Срочно / Снять срочность**
и **🤍 Заготовки готовы / ❤️ Снять готовность заготовок**. Готовность заготовок
снимает их паузу; включение паузы снимает готовность заготовок. Повторное нажатие
сердечка снимает только готовность, без включения паузы. Эти действия сохраняются
в базе и не меняют общую готовность заказа, срочность или паузу нанесения.
Паузы независимы: обе могут быть включены одновременно, повторное нажатие снимает
только выбранную паузу. Готовность не сбрасывает паузы и срочность.
В Telegram дополнительно есть кнопка **🚚 ДОСТАВКА**. Она включает или снимает
одноимённый тег в строке статуса. Отметка сохраняется в базе, переживает перезапуск,
смену готовности и редактирование текста/фото; номер заказа остаётся последней строкой.
Действия доступны в карточке и каждой строке сайта, в Telegram и в CorelDRAW
(карточка и выбранный заказ в списке). Статусы сохраняются в общей базе;
сайт и плагин обновляют их автоматически каждые пять секунд. Ручное обновление остаётся.
Черновик можно отметить срочным; готовность и паузы доступны после публикации карточки.

При обновлении сервера бот один раз добавляет новые кнопки к известным системным
карточкам текущего канала. Этот шаг меняет только клавиатуру, без замены текста,
фотографий или удаления сообщений. Сторонние сообщения не обрабатываются этим шагом.
Если Telegram сообщает, что исходная карточка отсутствует, бот сохраняет заказ и
не создаёт замену автоматически. Сайт показывает предупреждение под фотографиями;
действия производства продолжают работать в базе и CorelDRAW.
CorelDRAW обновляет состояния без замены редактируемого текста CDR. Если текст
карточки меняли в другой программе, сначала загрузите карточку с сервера перед публикацией.

## Приём заказов и этикетки

Откройте `/orders` на ПК приёмки и введите существующий ключ публикации.
Кнопка **Принять заказ** открывает форму с необязательными именем и количеством.
**Принять и печатать** выдаёт номер из общей очереди, сохраняет дату и постоянную
ссылку на карточку. Номер появляется в нераспределённых заказах. Если запрос
оборвался, **Повторить приём того же заказа** повторяет его с тем же ID нажатия;
дубли не создаются, даже после обновления страницы в той же вкладке.

Используется одна этикетка 80 × 110 мм: имя и количество остаются пустыми,
если их не указали. Приёмка сразу вызывает печать; повторная печать доступна
кнопкой **Печать этикетки**, без предварительного окна просмотра сайта.
В системном диалоге печати выберите бумагу 80 × 110 мм, масштаб 100%, отключите колонтитулы.
На этикетке есть номер, дата по Екатеринбургу, QR и Code128. Штрихкод содержит
год и номер (`2026/10001`), поэтому заказы разных лет не смешиваются.
При ошибке или отмене печати откройте ту же запись и распечатайте её повторно.
Регистрация заказа сама по себе не подтверждает, что принтер выдал бумагу.

### Печать без диалога на Windows

На производственном ПК с принтером установите отдельный модуль:
`https://evpmerch.com:9443/downloads/order-station-windows.zip`.
Распакуйте весь ZIP в папку, запустите `Install.cmd` из этой папки,
введите адрес и ключ рабочего сервера. Имена файлов в ZIP и код запуска CMD
содержат только ASCII; PowerShell-скрипты с русским текстом включены с UTF-8 BOM.
CorelDRAW и отдельно установленный Node.js не требуются. Установщик создаёт
ярлык **Заказы**, который открывает `http://127.0.0.1:4174/orders`.
Модуль получает актуальный интерфейс с рабочего сервера, работает только на localhost
и может запускаться в фоне при входе в Windows. Подключение хранится с DPAPI-защитой
для текущего пользователя в `%LOCALAPPDATA%\VanyaTools\OrderStation\data\connection.bin`.
Поменять подключение или автозапуск можно через ярлык **Настройки печати заказов**.
В настройках сайта ⚙ выберите формат этикетки, установленный физический принтер
для этого формата и нажмите **Сохранить принтер**. Выбор сохраняется после перезапуска
в `%LOCALAPPDATA%\VanyaTools\OrderStation\data\printing\settings.json`.
В модуле при отсутствии выбранного принтера или сбое печати показывается ошибка;
он не переключается на браузерный диалог. На каждом ПК модуль настраивается отдельно.

Для разработки остаётся `start-connected.ps1` и локальная страница на порту 4173;
этот старый способ использует сохранённое подключение плагина CorelDRAW.

Кнопка **Этикетка** печатает выбранный в настройках формат.
Маленькая метка: 45×22,5 мм, крупное имя
заглавными буквами, шрифт Roboto Condensed Bold (шрифт и лицензия включены в проект)
(два слова — две строки) и фактическая дата нажатия **Готово** по Екатеринбургу
в левом верхнем углу метки.
Для заказов в работе печатается плановый срок, при его отсутствии — только имя.
Дата повторной печати не заменяет дату готовности.
В настройках отдельно выберите принтер меток, например XP-365B: основной RICOH
и его бумага остаются настроенными для большой этикетки. Единственный принтер
с `XP`, `Xprinter` или `365` в имени предлагается автоматически; выбор нужно сохранить.
Метка отрисовывается в 360×180 точек (8 точек/мм), поворачивается на 180° и
печатается без диалога через драйвер Windows. В настройках драйвера XP задайте
зазор 3 мм, плотность 10, скорость 4; приложение не запускает калибровку перед
каждой печатью. Перед первым использованием откалибруйте зазор на принтере один раз.
На публичной странице без локального модуля доступен браузерный диалог печати.
Для RICOH выберите **A4 · этикетка 80×110 мм**: изображение печатается в натуральном
размере с отступом 10 мм на одном листе A4. Для этикеточного принтера выберите
бумагу **Этикетка 80×110 мм** и проверьте поддержку этого размера его драйвером.

Локальный сервер загружает актуальную этикетку с общего сервера, отрисовывает её
в 300 dpi и передаёт драйверу Windows через `StandardPrintController` без окон.
Сообщение «отправлена в очередь» означает приём задания Windows, а не подтверждение
выхода бумаги. Задания и их ID сохраняются в `data/printing/jobs`: потерянный ответ
можно повторить без создания второго задания. После прерывания во время передачи
задание помечается неопределённым; проверьте очередь и бумагу перед повторной печатью.
На обычном сайте без модуля используется браузерный диалог. На Linux и при
публичном/LAN-прослушивании локальная печать отключена; управление ею требует ключа.

Пакет собирается на Windows x64: `node station/package-station.mjs`.
Он включает только локальный модуль, Windows runtime и зависимости печати;
ключи, база заказов и токен Telegram в ZIP не включаются.

В CorelDRAW откройте сохранённый CDR и раздел **Номер с приёмки** в карточке:
**Загрузить нераспределённые** → выбрать номер → **Присвоить номер этой карточке**.
Добавленные кадры и введённый текст сохраняются. Сервер исключает номер из
нераспределённых и не допускает присвоение двум разным карточкам. Заполните
карточку и нажмите **Сохранить карточку заказа**. Сохраните CDR с привязкой номера.
Обе части плагина (DLL и помощник заказов) нужно обновить вместе.

Производство открывает `/orders`, сканирует штрихкод в поле поиска либо открывает
QR. Карточка доступна после ввода ключа сервера. После заполнения заказа можно
печатать ту же этикетку с заказчиком, технологией, описанием и количеством;
при большом объёме текста продолжение доступно по QR. Ссылка QR остаётся прежней.

Приём и локальное хранение карточек работают без Telegram. Если бот не настроен,
текст и фото сохраняются в `data/orders.sqlite` и `data/order-photos/`. Делайте
резервную копию всего каталога `data`. При настроенном боте публикация сохраняет
существующий процесс Telegram. Новые маршруты защищены тем же `X-Admin-Key`.

Для первоначальной проверки на одном ПК достаточно обычного локального запуска
ниже. Для подключения других рабочих ПК задайте постоянный LAN-адрес сервера,
чтобы напечатанные ссылки продолжали работать. Пример запуска в PowerShell:

```powershell
$env:PREVIEW_HOST = '0.0.0.0'
$env:PREVIEW_PORT = '4173'
$env:PREVIEW_PUBLIC_URL = 'http://192.168.1.50:4173' # заменить адресом вашего ПК
$env:PREVIEW_ALLOW_HTTP_LAN = '1'
$env:PREVIEW_ADMIN_KEY = 'ваш-ключ-публикации'
npm start
```

HTTP разрешён только явной настройкой для частных IPv4-адресов. Публичный сервис
по-прежнему требует HTTPS. Доступ к порту должен быть разрешён в локальной сети.
В плагине укажите тот же адрес и ключ сервера.

Будущая физическая кнопка отправляет `POST /api/orders/intake` с заголовком
`X-Admin-Key` и JSON `{"clientKey":"UUID-нажатия"}`. До подтверждённого ответа
контроллер должен повторять тот же UUID. Новый UUID означает новый заказ.
Сейчас печать запускается из браузера; автоматическая отправка на LAN-принтер
будет подключена после выбора модели, адреса и размера этикетки.

Проверки: `npm test` и `npm run build`. Тесты проверяют повторные запросы,
присвоение с двух ПК, сохранность данных, локальные карточки, Telegram и чтение
обоих кодов с отрисованной этикетки в разрешении 203 dpi.

## Фотографии заказов

Рабочий экран разделён на список слева (25% ширины) и карточку справа.
Приёмка находится внизу списка; общей шапки нет. Список автоматически обновляется
каждые пять секунд при открытой вкладке, также есть ручное обновление.
В карточке можно указать срок, изменить готовность, включить срочность и напечатать
этикетку. Активные срочные заказы находятся сверху и подсвечиваются; анимация
отключается при системной настройке уменьшения движения.
Срок находится рядом с именем: первый выбор сразу сохраняется, изменение или
удаление уже заданного срока требует подтверждения. Прокручивается только список
слева. Стрелки переключения кадров, зум, «Вписать» и полный экран находятся на фото.

В списке показывается первая миниатюра, в открытой карточке — все фотографии.
Доступны масштаб колесом, перемещение снимка и полноэкранный просмотр. Браузер загружает
миниатюры до 320 × 240 px, полный снимок запрашивается при открытии.
Фото доступны только с ключом сервера. Telegram `file_id` и токен бота браузеру
не передаются: сервер скачивает фото через `getFile` и хранит копии и миниатюры
в `data/order-photo-cache`. При замене снимка меняется ключ кеша.
Для старых карточек без сохранённых `file_id` остаётся ссылка на фото в Telegram;
номера сообщений сами по себе не позволяют скачать их через Bot API.

## Карточки заказов Telegram

Сервер принимает карточки от CorelDRAW через `/api/orders` с тем же ключом
`PREVIEW_ADMIN_KEY`, который используется для публикации превью. Токен бота и
канал находятся только на сервере в `.env.production`:

```text
ORDER_BOT_TOKEN=токен_бота
ORDER_BOT_CHANNEL=@имя_канала_или_chat_id
ORDER_BOT_ALLOWED_USER_IDS=123456789,987654321
ORDER_IMPORT_LEGACY=1
```

Последний параметр содержит числовые Telegram ID сотрудников, которым можно
менять статус кнопкой в старых карточках. Без него кнопка никому не разрешает менять
статус. Бот должен быть администратором канала с правом публикации и закрепления
сообщений. Номер заказа, ID фото и версия
карточки сохраняются в `/app/data/orders.sqlite`. Данные переживают пересборку
контейнера. Несколько ПК используют один бот и один номер заказа. Сервер
назначает номер формата `ММ###` (например, `10001`): первые две цифры — месяц
по Екатеринбургу, последние три — общий счётчик месяца с `001`.

Новая карточка публикует фото и текст в одном системном сообщении. Статус
меняется из плагина, сайта или кнопками Telegram. Номер заказа находится последней
строкой сообщения. Пока заказ в работе, карточка закреплена; готовая карточка
откреплена. По нажатию «Готов» сохраняются фактические дата и время завершения. Они видны
на сайте и в строке статуса Telegram по времени Екатеринбурга. При возвращении
заказа в работу отметка завершения сбрасывается; повторное нажатие «Готов»
для уже готового заказа не изменяет дату.
На сайте данные заказа показаны поверх фото, а шапка содержит кнопки действий.
Кнопка карандаша рядом с именем сохраняет новое имя в базе, этикетке и том же
сообщении Telegram. Изменение проверяет версию карточки и не заменяет фотографии.
Плагин может заменить фото
и текст или обновить только текст. Старые заказы с альбомом и отдельным
сообщением статуса, а также с одним составным фото продолжают работать в своих
форматах. Если запрос оборвался, повтор с тем же
ID карточки не создаёт дубль; незавершённую отправку следует сверить с каналом.

Администратор канала может исправить системную карточку обычным действием
Telegram **Изменить сообщение**. Сервер получает `edited_channel_post`, заново
распознаёт имя, источник и технологию, сохраняет остальные детали свободным
текстом и обновляет тот же заказ на сайте. Замена фото и изменение состава фото
в одном системном rich-сообщении переносятся целиком; в старом альбоме замена
отдельного снимка обновляет только соответствующую позицию. Удаление отдельного
сообщения/снимка обычного альбома не синхронизируется: Telegram не передаёт такое
событие. Видео и документы вместо фото не принимаются.

Номер, QR, срок, срочность, статус и дата готовности остаются прежними; служебный
низ сообщения восстанавливается из базы. Правки чужих и старых несистемных постов
не создают заказы и не запускают удаление сообщений. Нераспознанная или устаревшая
правка не меняет данные заказа; пояснение видно под фото на сайте. История правок
и предыдущие данные сохраняются в таблице `order_telegram_edits`; обработанные
события и собственные обновления бота не применяются повторно после перезапуска.
Доступ к прямому редактированию определяют права администраторов канала Telegram:
личность анонимного редактора канала Telegram не раскрывает, поэтому список
`ORDER_BOT_ALLOWED_USER_IDS` ограничивает кнопки, но не ручное редактирование постов.

Плагин хранит номер заказа и версию в свойствах CDR. Изменения с другого ПК
загружаются кнопкой «Загрузить карточку с сервера». Старый заказ можно открыть
по номеру в любом сохранённом CDR и поправить текст без исходных кадров.
Ключ подключения на ПК
сохраняется шифрованием Windows; при первом запуске подхватывается уже
настроенный ключ публикации превью.

Кнопки Telegram позволяют менять готовность и срочность; допустимые сотрудники
задаются через `ORDER_BOT_ALLOWED_USER_IDS`. Для переходного приёма сообщений
включите `ORDER_IMPORT_LEGACY=1` и разрешите боту удаление сообщений в канале.
Обрабатываются только новые сообщения после включения: например,
`Наталья Давыдова ВК Вышивка худи СТАН -125шт` или многострочный текст
`Эллина ТГ / ДТФ / футболки заказчика - 4шт` (вместо `/` — перенос строки).
Текст может быть подписью фотографии или альбома до десяти фотографий.
Для распознавания обязательны только имя заказчика, источник и технология.
Количество и срок извлекаются по возможности; произвольные или нераспознанные
детали сохраняются в описании и исходном тексте. Отсутствие количества или
некорректная дата не мешают созданию карточки.
Бот ждёт четыре секунды после последнего кадра, создаёт системную карточку
с номером и всеми фото, затем удаляет только исходные сообщения этого заказа.
При неоднозначном тексте или неподтверждённой публикации оригиналы сохраняются.
История обработок и исходные данные остаются в базе; старые сообщения канала
автоматически не преобразуются.

Постоянный адрес интерфейса: `https://evpmerch.com:9443/orders`.
Старые адреса с параметрами `v` или `version` перенаправляются на этот же адрес
без версии. HTML не кешируется, а файлы интерфейса получают новые имена при
обновлении — ссылка остаётся прежней. Фотографии и миниатюры хранятся в общем
буфере текущей страницы: переключение карточек, полный экран, фильтры и изменение
статусов используют уже загруженные снимки. Замена фото обновляет только его
версию. Буфер ограничен 96 МБ и 160 снимками; занятые открытыми компонентами
снимки освобождаются после закрытия. При смене ключа буфер очищается, после
перезагрузки страницы снимки загружаются заново. На другом ПК в настройках
нужно один раз ввести ключ рабочего сервера. Интерфейс запоминает ключ в
`localStorage` этого браузера для адреса сайта и восстанавливает подключение
после перезапуска браузера или ПК. Ранее сохранённый в текущей вкладке ключ
переносится автоматически. В настройках есть «Забыть ключ на этом ПК».
В приватном режиме или после очистки данных сайта ключ потребуется ввести снова.
Пометки карандашом и выделителем сохраняются кнопкой «Окей» отдельно для каждого
кадра в `order_photo_markup`. Для опубликованных заказов эта же операция добавляет
задание в устойчивую очередь `order_telegram_sync`: бот обновляет фото существующей
карточки, без новой публикации. В Telegram отправляется изображение с наложенными
штрихами, а сайт хранит исходное фото и редактируемые координаты. Очистка пометок
возвращает исходное изображение в Telegram. Идентификаторы опубликованных копий
хранятся в `order_photo_markup_media`, поэтому изменение статуса или текста в
Telegram не заменяет оригинал на уже размеченный кадр. Ошибка 429 откладывает
отправку до разрешённого Telegram времени; очередь переживает перезапуск сервиса.
Заменённые фотографии и архивные карточки не получают прежние пометки.
Вкладка «Экспресс» показывает счётчик всех заказов, отмеченных готовыми сегодня
по времени Екатеринбурга. Готовность давнего заказа тоже включается в ответ
списка, даже если он уже не входит в последние 100 карточек. При новой готовности
в левой колонке появляется уведомление; поиск, фильтры и выбранный кадр сохраняются.
Нажатие на уведомление открывает «Экспресс» со сброшенными фильтрами. Непрочитанные
уведомления и просмотренные события сохраняются на этом ПК и разделяются вкладками
того же браузера; повторный опрос и перезагрузка не создают новые сигналы.
При первом подключении старые готовности принимаются без оповещения. Уведомления
и отдельный звуковой сигнал настраиваются в «Готовность заказов». Пока уведомления
включены, список опрашивается и в фоновой вкладке; браузер может замедлять фоновые
таймеры. Звук требует нажатия на страницу после запуска браузера.
В настройках готовности громкость сигнала регулируется от 0 до 100% и сохраняется
для этого адреса сайта в браузере; начальное значение — 80%. «Проверить звук»
использует выбранную громкость, 0% полностью отключает звук. «Уведомления браузера»
запрашивают системное разрешение только при включении пользователем. Для проверки
есть отдельная кнопка. Новое уведомление показывает номер и имя клиента, нажатие
переводит сайт в «Экспресс». Запрещённое разрешение не запрашивается автоматически
повторно; инструкция отображается в настройках. Системное уведомление отправляется
без дополнительного звука ОС: громкость регулируется сигналом сайта. Сайт должен
оставаться открытым, фоновые вкладки поддерживаются.
Сигнал — одно нажатие записанного настольного колокольчика с коротким затуханием.
Запись встроена в интерфейс и загружается вместе с ним; повторная проверка
перезапускает сигнал, изменение громкости и выключение сразу применяются к звуку.
Источник записи: kleinhirn2000, https://freesound.org/people/kleinhirn2000/sounds/96521/,
CC0 1.0. Происхождение и обработка описаны в `src/assets/desk-bell.LICENSE.txt`.
При смене `ORDER_BOT_CHANNEL` новые карточки и
импорт используют новый канал; старые заказы сохраняют свои Telegram ID и канал
в базе. Чтобы обновлять их сообщения, бот должен сохранить доступ к старому каналу.

Сервис превью для вкладки **Публикация** Vanya Tools в CorelDRAW. Плагин
отправляет выделение; сервис впечатывает водяной знак и создаёт фрагменты
для просмотра по ссылке с масштабом 1:1. Список ссылок и досрочное удаление
находятся в плагине. Через 7 дней доступ истекает, а файлы удаляются автоматически.

## Запуск на этом компьютере

Для просмотра заказов с действующего сервера запустите `./start-connected.ps1`
из PowerShell в каталоге `preview-site`. Скрипт берёт адрес и ключ из сохранённых
настроек плагина, расшифровывая их средствами Windows; ключ рабочего сервера
не передаётся браузеру и не записывается в исходники. На странице `/orders`
используйте локальный ключ из `data/admin-key.txt`. Список, карточки и поиск
читаются с рабочего сервера без копирования заказов в локальную базу.
Доступные операции определяются по возможностям рабочего сервера. После его
обновления локальная страница также поддерживает приёмку, этикетки, срочность
и сроки, сохраняя изменения в общей рабочей базе. При подключении к прежней
версии отсутствующие операции отключаются.
Вне Windows можно задать `PREVIEW_ORDER_SERVER` и `PREVIEW_ORDER_SERVER_KEY`
в окружении процесса. Без этих переменных используется локальная база.

```powershell
cd D:\vanyaprog\corelmacros\preview-site
npm ci
npm run build
npm start
```

При первом локальном запуске сервер создаст ключ публикации, напечатает его
в терминале и сохранит в `data/admin-key.txt`. Вставьте его в сворачиваемом
блоке **Подключение** вкладки **Публикация**. Плагин хранит ключ средствами
шифрования Windows. Выделите объект или группу и нажмите **Опубликовать
выделение**. Исходные объекты остаются в документе.

Рабочий сервис размещён отдельно от основного сайта по адресу
`https://evpmerch.com:9443`; контейнер слушает только `127.0.0.1:4173`
за Nginx. Локальный `compose.yaml` остаётся для разработки.

## Обновление сервера из GitHub

Код сайта хранится в `main` репозитория `zmienkoivan/corelplugin`. На сервере
его checkout находится в `/opt/vanya-preview/repo`. Рабочие публикации и ключ
лежат отдельно в `/opt/vanya-preview/data` и `/opt/vanya-preview/.env.production`.
Из каталога checkout выполните:

```sh
sh preview-site/deploy/update-from-git.sh
```

Скрипт получает `main` с GitHub по SSH, принимает только обновление без
конфликтов и пересобирает только контейнер `vanya-preview`. Docker сам собирает
интерфейс из исходников Git, поэтому передача архива и установленный Node.js на
сервере не нужны. `origin` этого checkout использует ключ
`/root/.ssh/evpmerch_deploy_key`. Для первоначального размещения checkout:

```sh
GIT_SSH_COMMAND='ssh -i /root/.ssh/evpmerch_deploy_key -o IdentitiesOnly=yes' \
  git clone --branch main git@github.com:zmienkoivan/corelplugin.git /opt/vanya-preview/repo
git -C /opt/vanya-preview/repo config core.sshCommand \
  'ssh -i /root/.ssh/evpmerch_deploy_key -o IdentitiesOnly=yes -o BatchMode=yes'
```

Чистый файл временно передаётся на сервер и удаляется после создания копии
с водяным знаком. Водяной знак и фрагменты затрудняют использование превью,
но не исключают снимки экрана.

Максимум: 350 МБ, 70 Мп, 20 000 px по стороне. Плагин сохраняет 300 DPI,
пока выделение помещается в лимит; для большего макета выбирает 150 или
72 DPI. Размер на холсте сохраняется. Новые ссылки используют случайный
22-символьный идентификатор; прежние ссылки с UUID и ключом продолжают работать.

## Карточки Telegram

Рабочий канал использует native Rich Messages: фотографии, имя, источник и технология,
задание, компактные сведения о сроке и количестве, затем встроенные кнопки. Цвет
показывает активную срочность, паузы и отметки. Статус и номер заказа остаются внизу.
HTML Widgets пока доступны в production только в личной переписке с ботом и для
карточек канала не используются.

Новая разметка применяется при публикации, изменении состояния или нажатии
«Обновить карточку». При старте бот не переписывает текст прежних сообщений.
Существующие фотографии, номера и ревизии сохраняются. Ручные правки имени,
строки источника/технологий, задания и фотографий синхронизируются с сайтом;
служебные даты, статусы и номер защищены от изменения через текст сообщения.
Невидимые anchors разделяют редактируемые поля и служебную часть. Повреждённая
структура или устаревшая ревизия оставляют исходные данные в БД и фиксируют ошибку
для проверки. Обычные старые подписи и альбомы продолжают обрабатываться.
