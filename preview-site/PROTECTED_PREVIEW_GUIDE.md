# Публикация макета для просмотра в высоком разрешении

Инструкция для переноса механизма Vanya Preview в онлайн редактор макетов. Примерный стек: Node.js, Sharp, React и OpenSeadragon. Код ниже показывает ключевые части алгоритма; пути к файлам, авторизацию и обработку ошибок нужно встроить в новый проект.

## Что получает заказчик

Заказчик открывает временную ссылку, приближает макет до масштаба 1:1, переключает фон под прозрачными участками и видит физические размеры. Браузер получает только фрагменты **уже отмеченного водяным знаком** изображения. Чистый оригинал и печатный экспорт не выдаются через просмотрщик.

Это защита от простого скачивания, а не запрет на копирование экрана: посетитель может сделать скриншот или собрать полученные фрагменты обратно. Поэтому знак должен быть вписан в пиксели **до** нарезки, а оригиналы должны оставаться в закрытом хранилище.

## Схема данных

```text
Закрытый проект редактора / исходники
          │
          ▼
Серверный рендер в PNG с прозрачностью
          │
          ├─ определить размер и выбрать 300 → 150 → 72 DPI
          ├─ проверить лимиты
          ├─ вписать водяной знак в пиксели
          └─ удалить временный чистый PNG
          │
          ▼
PNG со знаком → пирамида WebP фрагментов 512 × 512
          │
          ▼
API с проверкой ссылки / срока / PIN → canvas просмотрщика
```

Хранить каждую публикацию удобно отдельно:

```text
private/previews/<random-id>/
  preview.json        # размеры, DPI, срок, параметры доступа
  marked.png          # полноразмерная копия со знаком; не раздавать статикой
  image.dz            # описание пирамиды Deep Zoom
  image_files/        # уровни и WebP фрагменты
```

Рабочий проект и исходные изображения должны жить **отдельно** от этой папки. При удалении публикации удаляется только её папка. Если заказчик редактирует макет в браузере, ему можно выдавать экранные копии исходников, а чистый печатный экспорт строить на сервере по данным проекта.

## 1. Размер и выбор DPI

Физический размер макета храните в мм независимо от его разрешения. Не меняйте ширину и высоту в мм, когда снижаете DPI.

```js
const LIMIT_PIXELS = 70_000_000;
const LIMIT_SIDE = 20_000;

function rasterPlan(widthMm, heightMm) {
  for (const dpi of [300, 150, 72]) {
    const width = Math.ceil(widthMm * dpi / 25.4);
    const height = Math.ceil(heightMm * dpi / 25.4);
    if (width <= LIMIT_SIDE && height <= LIMIT_SIDE &&
        width * height <= LIMIT_PIXELS) {
      return { width, height, dpi, pixels: width * height };
    }
  }
  throw new Error('Макет слишком велик даже при 72 DPI');
}
```

Пример для 550 × 750 мм:

| DPI | Пиксели | Мегапиксели | RGBA без сжатия |
| ---: | ---: | ---: | ---: |
| 300 | 6497 × 8859 | 57,6 | 219,6 МиБ |
| 150 | 3249 × 4430 | 14,4 | 54,9 МиБ |
| 72 | 1560 × 2126 | 3,3 | 12,7 МиБ |

Оценка памяти/несжатого растра: `width × height × 4` байта. **Это не размер итогового PNG или WebP**: вес сжатого файла зависит от содержания. Перед рендером показывайте DPI и ожидаемую оценку памяти, после обработки — фактический размер файла.

В действующем плагине расчёт находится в [`PreviewLibraryTab.cs`](../native/VanyaTools.Native/PreviewLibraryTab.cs), а растрирование временной копии выделения — в [`AiSelectionCapture.cs`](../native/VanyaTools.Native/AiSelectionCapture.cs). Для онлайн редактора растрируйте состояние проекта на сервере.

## 2. Водяной знак и нарезка на сервере

Сначала создайте временную директорию, примите или отрендерите чистый PNG, проверьте входной файл и размеры. Текущие лимиты Vanya Preview: до 350 МиБ на загрузку, 70 Мп и 20 000 px по каждой стороне. Сервер обрабатывает одну публикацию за раз, чтобы не переполнить память.

```js
import fsp from 'node:fs/promises';
import path from 'node:path';
import { randomBytes } from 'node:crypto';
import sharp from 'sharp';

sharp.concurrency(1);

const id = randomBytes(16).toString('base64url'); // 22 символа
const dir = path.join(previewsRoot, `.building-${id}`);
const source = path.join(dir, 'source.png');
const marked = path.join(dir, 'marked.png');

await fsp.mkdir(dir);
// Здесь сервер создаёт source из проекта или принимает приватную загрузку.
const meta = await sharp(source, { limitInputPixels: 70_000_000 }).metadata();
if (!meta.width || !meta.height || meta.width * meta.height > 70_000_000 ||
    meta.width > 20_000 || meta.height > 20_000) {
  throw new Error('Превышен предел размера изображения');
}

// watermarkSvg — SVG-буфер с логотипом/надписью и прозрачностью.
// Он должен покрывать всю площадь повторяющимся узором.
await sharp(source, { limitInputPixels: 70_000_000 })
  .composite([{ input: watermarkSvg, tile: true }])
  .withMetadata({ density: dpi })
  .png({ compressionLevel: 6 })
  .toFile(marked);
await fsp.rm(source, { force: true });

await sharp(marked, { limitInputPixels: 70_000_000 })
  .webp({ quality: 90, effort: 4 })
  .tile({ size: 512, overlap: 0, layout: 'dz' })
  .toFile(path.join(dir, 'image.dz'));

// После записи preview.json атомарно переименуйте .building-<id> в <id>.
```

В рабочей версии знак `evpmerch.com` хранится как **контуры букв** в SVG, поэтому не зависит от установленных на сервере шрифтов. Он повторяется по всему изображению. Плотность сейчас 32%. Лучше добавлять в знак также номер заказа или получателя, если нужна возможность установить источник утечки. Реализация: [`server/index.mjs`](server/index.mjs) и [`watermark-outline.mjs`](server/watermark-outline.mjs).

Нельзя делать знак только HTML/CSS слоем поверх canvas: его легко скрыть. Нельзя включать в публичную выдачу чистый PNG, исходник проекта или URL к ним.

## 3. API и доступ

Минимальные маршруты:

| Метод и путь | Назначение | Доступ |
| --- | --- | --- |
| `POST /api/previews` | Создать публикацию | Владелец проекта |
| `GET /api/previews/:id` | Заголовок, px, DPI, срок | По ссылке, при необходимости PIN |
| `GET /api/previews/:id/tile/:level/:x_:y.webp` | Один фрагмент | Та же проверка для каждого запроса |
| `GET /api/previews` | Список публикаций | Владелец проекта |
| `DELETE /api/previews/:id` | Досрочно удалить | Владелец проекта |

Случайный ID из 16 байт служит ключом доступа по ссылке. Любой получивший ссылку может смотреть превью. Если этого мало, добавьте PIN, пароль или вход в аккаунт заказчика. PIN храните как соль + стойкий хеш, а не открытым текстом. Срок ссылки проверяйте на запросе **метаданных и каждого фрагмента**, чтобы уже открытая страница перестала работать после истечения срока или удаления.

```js
async function authorizePreview(id, suppliedPin) {
  const manifest = await readManifest(id);
  if (!manifest) throw httpError(404, 'Превью не найдено');
  if (Date.now() > Date.parse(manifest.expiresAt))
    throw httpError(410, 'Срок ссылки истёк');
  if (manifest.pin && !verifyPin(suppliedPin, manifest.pin))
    throw httpError(401, 'Введите PIN');
  return manifest;
}
```

Метаданные должны содержать `width`, `height`, `dpi`, `expiresAt`, `title`; исходный путь к файлу наружу не выдаётся. Для метаданных используйте `Cache-Control: no-store`, для фрагментов — приватное краткое кеширование. Старые папки удаляйте по расписанию. В текущей реализации ссылка живёт семь дней, очистка идёт при запуске сервера и каждый час. Код маршрутов и проверки: [`server/index.mjs`](server/index.mjs).

**Для нового редактора не помещайте ключ администратора в публичный JavaScript.** Пусть сервер определяет права пользователя по его сессии и проверяет владение проектом при создании, просмотре списка и удалении публикаций.

## 4. Canvas просмотрщика

OpenSeadragon сам выбирает подходящий уровень пирамиды и загружает нужные фрагменты. Основная конфигурация выглядит так:

```jsx
const viewer = OpenSeadragon({
  element: container,
  drawer: 'canvas',
  showNavigationControl: false,
  showNavigator: true,
  loadTilesWithAjax: true,
  ajaxHeaders: { 'X-Preview-Pin': pin },
  maxZoomPixelRatio: 1,
  imageSmoothingEnabled: true,
  minZoomImageRatio: 0.75,
  tileSources: {
    width: meta.width,
    height: meta.height,
    tileSize: 512,
    getTileUrl: (level, x, y) =>
      `/api/previews/${id}/tile/${level}/${x}_${y}.webp`,
  },
});

viewer.addHandler('tile-drawing', ({ context }) => {
  context.imageSmoothingEnabled = true;
  context.imageSmoothingQuality = 'high';
});

// В React useEffect верните () => viewer.destroy().
```

Увеличение 1:1 означает соответствие пикселей картинки и canvas, **не физический размер печати на экране**. Выше 1:1 новый материал не появляется. Сглаживание canvas помогает избежать заметных «лесенок» при масштабировании в Chrome, но не добавляет деталей низкому разрешению. На медленном соединении показывайте индикатор до завершения загрузки нужных фрагментов.

Прозрачность видна за счёт CSS-фона **под canvas**: шашки, тёмный, светлый или цвет пользователя. Физические размеры подписываются из метаданных:

```js
const widthCm = meta.width * 2.54 / meta.dpi;
const heightCm = meta.height * 2.54 / meta.dpi;
```

Рабочий компонент находится в [`src/main.jsx`](src/main.jsx). Он также показывает масштаб, кнопку 1:1, «Вписать», срок ссылки и индикатор загрузки.

## Порядок внедрения в онлайн редактор

1. Введите для проекта физические размеры, список слоёв и закрытые исходники.
2. Сделайте серверный рендер выбранной версии проекта в PNG с альфа-каналом.
3. Реализуйте выбор DPI и лимиты до запуска тяжёлой обработки.
4. Впечатайте знак, удалите временный чистый рендер, создайте пирамиду фрагментов.
5. Храните публикации отдельно от проектов; добавьте ссылку, срок и удаление.
6. Раздавайте метаданные и каждый фрагмент через проверяющий API.
7. Подключите canvas просмотрщик и подписи размеров.
8. Печатный экспорт оставьте отдельной серверной операцией с собственными правами доступа.

Отказ от пунктов 2 и 8 ослабит схему: если браузер заказчика уже загрузил чистые полноразмерные исходники для редактирования, защитить их последующим «запретом скачивания» в просмотрщике невозможно.
